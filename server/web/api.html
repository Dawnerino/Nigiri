Where to call: two ways into the same models

The gateway proxies every stage and adds the one-shot pipeline. Each stage also runs as its own service on its own port, so you can talk to a single model directly and skip the rest.
PortServesNotes
8765 Gateway: web UI + /v1/* + /translate + /api/pipeline Start here. This is the port run.sh prints.
9101 Speech-to-text (whisper.cpp) Also answers GET /health and GET /v1/models.
9102 Translation shim Adds POST /translate on top of the passthrough.
9202 Raw llama-server behind the translator Full llama.cpp OpenAI API, no prompt wrapping.
9103 Text-to-speech Also answers GET /health and GET /languages.
Ports 9101–9202 are loopback-only. The engine processes bind to 127.0.0.1 no matter what you pick in Setup, so they are reachable from this machine only. --host 0.0.0.0 (or Setup → Network) rebinds the gateway for LAN use, not the engines. There is no authentication on any of them.

1 · Speech-to-text

Audio in, text out. This is the only endpoint that takes a multipart form, so there are no JSON braces involved.
POST /v1/audio/transcriptions gateway 8765 · direct 9101
Content-Type: multipart/form-data — returns application/json

Form fields

FieldAccepts
filerequired The audio. Anything ffmpeg can decode — wav mp3 m4a ogg webm flac mp4. Resampled to 16 kHz mono internally, so sample rate does not matter.
modeloptional A downloaded STT model id, e.g. large-v3-turbo-q5_0. Leave it empty to use whatever you chose in Setup.
languageoptional ISO-639-1 code (en, es, ja…) or auto. Default auto.
promptoptional Whisper initial prompt — useful for spelling names and jargon consistently.
curl -X POST http://localhost:8765/v1/audio/transcriptions \
  -F file=@speech.wav \
  -F model=large-v3-turbo-q5_0 \
  -F language=auto
import requests

r = requests.post(
    "http://localhost:8765/v1/audio/transcriptions",
    files={"file": open("speech.wav", "rb")},
    data={"model": "large-v3-turbo-q5_0",
          "language": "auto"},
)
print(r.json()["text"])
const fd = new FormData();
fd.append("file", fileInput.files[0]);
fd.append("language", "auto");   // model omitted → your Setup choice

const r  = await fetch("/v1/audio/transcriptions", { method: "POST", body: fd });
const { text } = await r.json();

Response

{
  "text": "Hello there, how are you today?",
  "model": "large-v3-turbo-q5_0",
  "language": "auto",
  "duration_ms": 2039.5
}
model is not whisper-1. It is validated against the models actually downloaded, so the OpenAI default fails with 400 unknown model 'whisper-1', have ['large-v3-turbo-q5_0']. Omit the field, or list valid ids with GET http://localhost:9101/v1/models.

2 · Translation

Text in, text out — JSON body, no file. Two shapes: a purpose-built one that returns just the translation, and an OpenAI passthrough if you already have a chat client.
POST /translate gateway 8765 · direct 9102
Content-Type: application/json — returns application/json

JSON body

KeyAccepts
textrequired The string to translate. Empty → 400 text required.
targetoptional A full language name — Spanish, Japanese, English. Not a code. Default English. This is the only key that steers the output.
sourceoptional Informational — echoed back in the response but never sent to the model, which detects the source language itself. Safe to omit.
curl -X POST http://localhost:8765/translate \
  -H 'content-type: application/json' \
  -d '{"text":"Good morning, the meeting is at nine.","target":"Spanish"}'
import requests

r = requests.post(
    "http://localhost:8765/translate",
    json={"text": "Good morning, the meeting is at nine.", "target": "Spanish"},
)
print(r.json()["translated"])
const r = await fetch("/translate", {
  method: "POST",
  headers: { "content-type": "application/json" },
  body: JSON.stringify({ text: "Good morning.", target: "Spanish" }),
});
const { translated } = await r.json();

Response

{
  "translated": "Buenos días, la reunión es a las nueve.",
  "source": "auto",
  "target": "Spanish",
  "model": "hy-mt1.5-1.8b"
}

Or: OpenAI chat passthrough

POST /v1/chat/completions gateway 8765 · direct 9102 · raw 9202 
curl -X POST http://localhost:8765/v1/chat/completions \
  -H 'content-type: application/json' \
  -d '{"messages":[{"role":"user","content":"Translate to Spanish: good morning"}],
       "temperature":0,"max_tokens":256}'
This is a raw passthrough to llama-server — it does not add the translation prompt. You get a standard OpenAI choices[0].message.content envelope back, and you must phrase the instruction yourself. Use /translate for clean output.

3 · Text-to-speech

Text in, raw audio bytes out. The body is JSON but the response is not — do not call .json() on it.
POST /v1/audio/speech gateway 8765 · direct 9103
Content-Type: application/json — returns audio/wav (binary, not JSON)

JSON body

KeyAccepts
inputrequired The text to speak. Named input, not text — same as OpenAI's speech API. Empty → 400 input text required.
voiceoptional One of F1 F2 F3 F4 F5 M1 M2 M3 M4 M5 for supertonic-3. Default M1.
languageoptional A full language name — Spanish, Japanese. Not a code.
response_formatoptional Accepted for OpenAI compatibility but ignored — the reply is always WAV.
curl -X POST http://localhost:8765/v1/audio/speech \
  -H 'content-type: application/json' \
  -d '{"input":"Hola a todos","voice":"M1","language":"Spanish"}' \
  --output speech.wav
import requests

r = requests.post(
    "http://localhost:8765/v1/audio/speech",
    json={"input": "Hola a todos", "voice": "M1", "language": "Spanish"},
)
r.raise_for_status()
open("speech.wav", "wb").write(r.content)   # .content, not .json()
const r = await fetch("/v1/audio/speech", {
  method: "POST",
  headers: { "content-type": "application/json" },
  body: JSON.stringify({ input: "Hola a todos", voice: "M1", language: "Spanish" }),
});
const url = URL.createObjectURL(await r.blob());   // play it, or download it
The key is input. Posting {"text": "…"} is the single most common mistake here and returns 400 input text required.
Unknown voice → 500 synthesis failed: Voice style 'X' not found. Available voice styles: F1, F2, F3, F4, F5, M1, M2, M3, M4, M5. Live language list for the model you picked: GET http://localhost:9103/languages or GET /api/languages on the gateway.

4 · Full pipeline (one shot)

Audio in, spoken translation out — STT → translate → TTS in a single call. Multipart body, JSON response, audio returned as base64.
POST /api/pipeline gateway 8765 only
Content-Type: multipart/form-data — returns application/json

Form fields

FieldAccepts
filerequired Source audio — same formats as stage 1.
sourceoptional ISO-639-1 code (en, es…) or auto. Default auto. Handed to Whisper as the spoken-language hint.
targetoptional Full language name — Spanish. Default English.
curl -X POST http://localhost:8765/api/pipeline \
  -F file=@speech.wav \
  -F source=auto \
  -F target=Spanish \
  -o result.json

# the spoken translation is base64 inside the JSON:
#   result.json -> .audio_b64
base64 -D result.json | jq -r .audio_b64 | base64 -D > spoken.wav
import base64, requests

r = requests.post(
    "http://localhost:8765/api/pipeline",
    files={"file": open("speech.wav", "rb")},
    data={"source": "auto", "target": "Spanish"},
)
out = r.json()
print(out["transcript"], "->", out["translated"])
open("spoken.wav", "wb").write(base64.b64decode(out["audio_b64"]))
const fd = new FormData();
fd.append("file", fileInput.files[0]);
fd.append("target", "Spanish");

const r   = await fetch("/api/pipeline", { method: "POST", body: fd });
const out = await r.json();
audio.src = "data:audio/wav;base64," + out.audio_b64;

Response

{
  "transcript": "The meeting starts soon and everyone is waiting in the room.",
  "translated": "La reunión comienza pronto, y todos están esperando en la sala.",
  "audio_b64": "UklGRiQAAABXQVZFZm10IBAAAAABAAEAgD4AAAB9AAACABAAZGF0YQAAAAA="
}
Errors name the stage that failed: 502 STT failed: …, 502 translation failed: …, 502 TTS failed: …, and 422 empty transcript when Whisper returns no text at all. Note that near-silence is not an error — Whisper hallucinates a phrase (a 1 s silent file came back as “Thank you.” with HTTP 200), so check the transcript before trusting the audio. A missing ffmpeg is called out with the install command for your OS.

Health & discovery

Cheap GETs to check what is up and what it will accept before you post anything.
RequestReturns
GET /health every port On the gateway: {"ok": true, "stages": {"stt": …, "translator": …, "tts": …}}. On each engine: its own detail — STT names its binary and downloaded weights, the translator reports model + upstream, TTS reports resident, languages and the last error.
GET /docs gateway FastAPI's interactive Swagger console for the gateway routes — post straight from the browser.
GET /v1/models port 9101 only The valid model ids for stage 1. 404 on the gateway — ask the STT port.
GET /languages port 9103 Languages the chosen TTS voice model can speak.
GET /api/languages Same list, from the gateway.
GET /api/stack/state Everything this page is built from: chosen models, devices, ports, per-stage health, memory.
GET /api/setup/status Full catalog, what is downloaded, and whether each engine's Python runtime is installed.

No API key is required on any port, and CORS is * — so a browser app on any origin can call Nigiri directly. Treat the machine as trusted.
